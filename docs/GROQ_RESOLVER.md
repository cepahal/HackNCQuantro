# Groq resolver integration

The public analyze, ingest and Photon webhook paths use `backend/services/resolution/run.py`. Existing ReportV2 2.1, Tiger tables, report URLs and Photon transport remain compatible. The supplied prototype handles caption/audio-based source discovery and assessment. The active resolver follows the supplied Groq, title-and-quote search, full-transcript and RapidFuzz method. It does not invoke the legacy Gemini window matcher.

## Active flow

1. Validate the URL and atomically reserve a Tiger job. Completed jobs return their existing report; other existing IDs cannot be overwritten.
2. Attempt the submitted clip download, then read cached/native YouTube captions. If YouTube blocks the server, the configured SerpAPI transcript engine can provide the complete available caption text. If captions are absent, use the downloaded clip or fetch audio and transcribe with Groq `whisper-large-v3-turbo`. FFmpeg converts video to mono 16 kHz MP3 and chunks long audio at 20 minutes. Instagram and TikTok require a successful media download. Downloaded media is saved through the existing Tiger media store.
3. Use Groq `openai/gpt-oss-120b` to propose a speaker/event query and a verbatim phrase. Search bounded observed speech phrases and the cleaned submitted title. In parallel, one Groq `browser_search` request independently searches for fuller YouTube recordings using the submitted title and transcript. Only links present in executed search-tool results are admitted, never URLs invented in the assistant's answer. Reserve up to four browser-search positions, interleave and deduplicate, then inspect at most twelve recordings of at least 30 seconds or unknown duration. At most six candidates use the slower audio fallback. An optional `YOUTUBE_API_KEY` uses the official Data API; otherwise yt-dlp search needs no additional key. Failed or empty direct searches use the configured SerpAPI YouTube engine. A separate unquoted observed-speech query can recover relevant recordings even when exact searches returned unrelated hits. Browser-search failure preserves these existing discovery paths; its links remain unverified until aligned against timed speech.
4. Compare real timed candidate transcripts using RapidFuzz partial-ratio matching. Scores below 75, generic/tiny phrases, repeated ambiguous passages and missing time bounds cannot verify a match. The score is a heuristic, not measured accuracy or factual reliability.
5. Locate the matched passage using actual caption/ASR segments, retain up to 60 seconds of surrounding speech on either side, and reject repeated short excerpts that supply no surrounding context. Reject a single contiguous match when a distinctive ending from the clip occurs verbatim elsewhere in the source but is unsupported inside the returned interval. This prevents a strong opening match from hiding an excluded conclusion; it does not establish original-upload identity or diagnose physical editing.
6. Use Groq to explain the clip and compare source context, with optional caption assessment. Every quotation must occur within one supplied sentence. One bounded repair is allowed after invalid schema/evidence; validation is never relaxed. Incomplete coverage cannot establish that no material context is missing. A failed language assessment preserves an already aligned source and an extractive transcript summary with assessment marked unavailable. Search failure remains an error rather than being silently reported as no match.
7. Persist the sanitized report in Tiger, complete the job, then deliver through the existing Photon bridge if a conversation was supplied. A delivery failure does not delete a saved report.

The caption and search fallbacks feed the original full-transcript matcher rather than a different analysis pipeline. Submitted captions with fewer than six word tokens and fewer than forty alphanumeric characters in valid timed speech trigger one independent Whisper attempt when configured. Untimed final cues remain available for discovery, but do not suppress this recovery check. This attempt bypasses the sparse-caption cache; only a result that adds valid timed speech replaces it. A failed or weaker recovery preserves the original captions, including legitimate short utterances. When no local video was acquired, recoverable sparse-caption cases can use the existing bounded native-YouTube reader once. Terminal access/provider errors still exclude that reader. This is a discovery-quality check, not a determination that the captions are false.

Provider cue starts delimit caption windows when actual cue ends are absent. These are explicitly labeled as cue windows, not word-level audio endpoints. A final cue without an actual end or known video duration remains available for discovery, but cannot manufacture a timed sentence. Unknown recording duration stays null. Exhausted caption and audio access remains a structured retrieval error; no provider can guarantee access to private, deleted or blocked recordings.

Temporary transcription failures at the media/native-reader boundary retry after exactly three seconds, with at most three wrapper attempts. Permanent access, configuration and invalid-response errors do not retry. Existing Groq SDK retries remain separate, so this wrapper limit is not a total HTTP-request limit. Exhausted optional recovery preserves usable captions and does not restart or duplicate the job.

## Configuration and deployment

Set `GROQ_API_KEY` privately on the backend and `GROQ_LLM_MODEL=openai/gpt-oss-120b`. Use `SEARCH_PROVIDER=youtube` for the supplied discovery method, or retain the existing valid provider setting. Pair `SEARCH_FALLBACK_PROVIDER=serpapi` with the private `SEARCH_FALLBACK_API_KEY` for hosted caption and YouTube-search recovery. The existing `GEMINI_API_KEY` enables the bounded independent native-YouTube reader described below; the core matcher remains unchanged. `RESOLUTION_DOWNLOAD_VIDEO=false` skips the optional submitted video download but still permits caption/audio recovery. Keep the existing Tiger URLs, CA, table prefix, Photon credentials, `REPORT_BASE_URL` and frontend origin. The frontend needs only its existing public backend URL. Never put provider keys in frontend variables or tracked environment files.

`GROQ_SOURCE_SEARCH` defaults to enabled when the existing Groq key is configured; set it to `false` to disable the extra browser-search request. This request uses `openai/gpt-oss-120b`, required `browser_search`, low reasoning effort, a 2,500-token completion cap, no SDK retries, and a 50-second outer deadline. It does not request structured output because that mode is incompatible with browser search. See [Groq browser-search documentation](https://console.groq.com/docs/tool-use/built-in-tools/browser-search). No new provider account or dependency is required.

## Independent YouTube recovery

Native caption/cache, hosted SerpAPI captions and Whisper audio remain the normal evidence paths. If no local recording was acquired and the final failure is a classified authentication challenge, download failure or unavailable format, the existing Gemini public-YouTube reader starts one bounded recovery sequence, with the temporary-failure retries described above. This reader uses Google's video ingestion rather than downloading from Render. It has a token preflight, bounded 60-second window, strict transcript validation and modality checks. Explicit valid `t`, `start` or fragment timestamps select that window; returned timestamps stay absolute. Invalid/conflicting offsets fail before the reader is called. A prior acquisition failure followed by missing local-ASR configuration can also use this independent route. Private/deleted/region-restricted recordings, no audio, oversized files and provider authentication/rate errors do not trigger this recovery. Existing-file ASR errors do not start another provider.

Recovered speech feeds the same discovery, candidate scoring, temporal alignment and surrounding-context checks. Only timestamp-backed candidate words contribute to the match score; untimed final cues remain discovery clues. Partial windows do not establish full video duration or coverage. Stale local-file references do not discard independent captions. MP4 export still requires source recording bytes; a failed export preserves the source report. Google's supported public-URL input and clipping behavior are documented in [Video understanding](https://ai.google.dev/gemini-api/docs/video-understanding); it does not return the original MP4 to this application.

The results page is currently in diagnostic mode: the best matched recording or explicitly unverified top lead appears beside a terminal panel. The previous result panels remain in a hidden container in `ReportPage.tsx`, with their components intact. Landing and navigation are unchanged. Remove that wrapper's `hidden` attribute and `legacyPanels` class to restore those panels.

## Diagnostic output

The terminal includes the complete public ReportV2 and DisplayModel JSON without summary truncation, plus newly captured resolver events. Copy and download export the same full text. Transcript text, metadata, candidate queries/scores, selection or rejection reasons, alignment, context, comparison, warnings and measured stage timings are included when recorded. Unknown values remain null. Failed jobs can expose their captured events without requiring a completed report.

`GET /reports/{report_id}/diagnostics` returns `job_id`, `capture_status`, `events` and `terminal_output`. Capture is per job, persisted in the additive Tiger `{prefix}analysis_diagnostics` table, and never changes ReportV2 2.1. Existing `ensure_schema()` creates the table. Diagnostic storage failures must not fail the analysis. The report gateway permits this suffix only under its existing report allowlist.

This is structured output captured from the integrated resolver, not intercepted global server stdout. Historical reports have no retroactive query/score/timing capture and explicitly return `capture_status="unavailable"`; their saved report data is still displayed. Public diagnostics exclude credentials, local file paths, raw provider exceptions and other jobs' logs. Original CLI `FILE` is represented by a downloaded boolean and media identifier instead of a filesystem path.

The QR signup is still served by the backend. Fresh provider registration checks and no-store responses prevent cached enrollment status. Durable reconciliation markers prevent a removed/restored user or changed line from reviving an old welcome confirmation. New iMessage summaries use three ordered messages: reliability TL;DR, short explanation, report link. Accepted-part receipts prevent automatic replay after a partial or ambiguous send; `accepted` does not prove handset delivery.

Deploy the tested main commit to Render manually, then deploy that same main revision to Vercel. Existing reports keep their saved analysis; submit a new job to exercise the new resolver. Restore a prior Render deployment and Vercel deployment for rollback; no destructive schema migration is needed.

The observed lexical score was 96.3, not a claim of 96.3% accuracy. The subsequent summary guard explicitly qualifies incomplete coverage.

These cue-window endpoints are coarser than the native-caption baseline above. Cold hosted-caption requests hit the former 12-second limit, so the bounded caption timeout was increased to 30 seconds.

Focused tests cover timed matching, negative and ambiguous passages, malformed citations, one-shot repair, partial coverage, source retrieval failures, search errors, no-match reports, idempotency, sanitization, metadata nulls, Tiger persistence and delivery failures. Existing modular pipeline tests remain explicitly scoped to their legacy implementation, alongside the new active-resolver tests.

Public platform retrieval can still be blocked, region-restricted, unavailable or require authentication. No universal retrieval guarantee or 94% accuracy claim is made. The inherited network guard remains enabled; its prohibition on yt-dlp runtime subprocesses can limit bot-challenge handling. Candidate audio fallback is bounded to 90 minutes, chunked within Groq upload limits and slower than captions. Visual edits, deepfakes, speaker identity, earliest-upload provenance and factual truth are not assessed. Actual QR enrollment and all three iMessages arriving on a handset require a live user test after deployment.

## Sentence-based context video

The active resolver now selects 1–3 adjacent complete sentences before and after the matched passage. Caption blocks are joined using punctuation; incomplete/unreliable sentence timing falls back to five seconds on that side. A bounded Groq selection chooses sentence counts only, never timestamps. If that request fails validation or times out, the nearest two available sentences are selected. Sentences crossing the matched boundary are completed where possible. Selection is an estimate, not a guarantee of sufficient context; timing remains at caption precision.

The chosen original source is exported as one continuous H.264/AAC MP4 with fast-start metadata and visible “Context before”, “Your clip’s passage”, and “Context after” labels. The user clip is not prepended. The selected context also feeds the existing comparison, so the explanation uses the same surrounding transcript. The output is persisted through `TigerDataPostStore` and played using the existing range-enabled `/media/{media_id}` endpoint. Temporary inputs and image overlays are removed after persistence. No worker path is returned in the public report.

Report schema 2.1 gains nullable, backwards-compatible `context_video` (PublicMediaAsset) and `context_selection` (selected sentences/bounds/fallback details). Older reports still render their original source. New successful exports play in the existing primary source player; attribution still links to the full source. No database migration or new API key is required. Pillow and FFmpeg are already declared in the backend image.

`CONTEXT_VIDEO_ENABLED=true` is the default. Set it to `false` to skip both the new selection and rendering stage. Downloads remain subject to platform restrictions; encoding is bounded to 120 seconds and excerpts to five minutes. Failure to download, encode, or persist a context video adds a public limitation and retains the existing source report. Full-source retrieval and encoding add latency; this is not a sub-20-second guarantee. Existing saved reports are unchanged; submit a new job after deploying both backend and frontend from the same revision.

Validation covers real FFmpeg output, audio/video duration agreement, on-frame label colors, missing audio, invalid bounds, temporary-file cleanup, successful-storage-before-exposure, report persistence/idempotency, nonfatal export failure, generated wire types, and frontend context playback/source attribution. External YouTube access and production Tiger credentials still depend on the deployment environment.
